# Xirius 1.1.0-beta.39

This beta is for Windows 10 and 11 (x64). To receive beta updates in the app, turn on **Receive beta versions** in Settings.

## Changed

- A song now opens as you last saved it. Changes you did not save are no longer written into the song file. They are kept as a draft and listed in the song's versions.
- Closing a song, quitting, opening another song or updating now asks whether to save your changes if there are any: **Cancel**, **Don't Save** or **Save**. Don't Save keeps the changes as a draft, and the next time you open the song it starts from your last save.
- A new song that was never saved asks to be saved before you leave it. If you choose Don't Save, the song is moved to the Recycle Bin.
- The top bar shows **Unsaved** while the song differs from its last save, including plugin presets and plugin settings. If you undo back to the saved state, it shows **Saved** again. A new, untouched song shows nothing.
- In the version list, your saves are shown as **Saved**, and automatic drafts are shown as smaller **Draft** rows.
- After a crash, the recovery card now says that your work was restored from a draft and that the song file stays as it was until you save. **Discard** is now **Go back to the saved state**.
- Every 30 seconds, the draft now also picks up the current state of open plugins, without pausing the window or the sound.
- Ctrl+Shift+S is now **Save As**. Turning every solo off moved to Ctrl+Alt+S.
- The command line and AI assistants connected through MCP no longer write the song file after each change. The song file changes only when they run `project.save` or `project.save-as`.

## Known issues

- Xirius may continue using CPU while the confirmation for closing a song or quitting is open. This is under investigation.

If the in-app update from 1.1.0-beta.2 or 1.1.0-beta.3 fails, close Xirius and use the installer on this page.
