# GPUI スパイクの合否と判定（UI-028）

2026-10-19 に記録。4〜6 週のスパイクの結果と、GPUI で続けるかの判定をまとめる。
測定はこの PC（Windows 11、Ryzen 9 7950X、RTX 5070、release ビルド、窓は表示の外）で行った。

## 5 つの条件の合否

| # | 条件 | 合否 | 記録 |
|---|---|---|---|
| 1 | 200 トラックの波形と 10,000 ノートのピアノロールを 60fps 以上でスクロール・ズームできる（UI-023） | △ | この PC では timeline-scroll / timeline-zoom は合格。ズームを往復する pianoroll-scroll-zoom・spike1-all-moving は 3 回中 0〜13 フレーム落ち（p99 22〜28 ms）。ピアノロールの描画を、同色の連続行と重なるノートを 1 つの quad にまとめる直しを入れた後も、ズームの往復では散発的に落ちる。**中くらいのノート PC での計測は 1.0 の後に確認する** |
| 2 | 再生中のメーター 64 本がほかの操作を妨げずに更新される（UI-024） | △ | meters-only は 3 回とも合格。spike2-meters-scroll-zoom-drag は 3 回中 1〜8 フレーム落ち（p99 20〜28 ms）。メーターの描画自体は軽く（p99 0.4 ms）、落ちはピアノロール側の描画が越えたフレームに出る。実画面の --bench --mixer は後述。**中くらいのノート PC では 1.0 の後に確認する** |
| 3 | Windows と macOS で CLAP / VST3 のエディターを別ウィンドウで開き、中の文字欄にキー入力できる（UI-025） | △ | Windows の VST3 は開ける。CLAP・macOS・文字欄への実際のキー入力は未確認（1.0 の後の実機確認） |
| 4 | 日本語 IME でトラック名を入力でき、スクリーンリーダーでトラック一覧を読める（UI-026） | ○ | トラック名の欄はパレットと同じ EntityInputHandler の経路で IME の変換・確定が通る（単体試験）。トラック一覧は AccessKit の Tree/TreeItem、入力の一覧は RadioButton の選択状態つきで、UI Automation で読めることを parked 窓への試験（tests/uia_window.rs）で確かめた。VoiceOver・ナレーターでの実際の読み上げは 1.0 の後に確認する |
| 5 | 固定した GPUI の版を上流の新しい版へ上げる作業を 1 回試し、時間を記録する（UI-027） | ○ | 2026-10-19 に 0.3.8 → 0.3.9（zed@279fe07 → 93d7456）へ試した。手順・かかった時間・直した箇所は下の「版の更新の記録」 |

## 判定

**GPUI で続行する。** Qt 6 / QML + cxx-qt への切り替えは起こさない。

理由:

- 条件 4・5 は合格。UIA のツリーが実際のスクリーンリーダーの読み方で取れること、上流への追従が現実的な費用であることが確かめられた。
- 条件 1・2 のフレーム落ちは GPUI ではなく自分の描画経路（1 フレームに数千の quad を積む所）に起因し、まとめ直しで改善している。描画の直しで届く見込みが残っている。
- 条件 3 の残りは実機が要る確認で、フレームワークへの疑いではない。

## 版の更新の記録（UI-027）

2026-10-19、gpui-pre / gpui-pre-platform の `=0.3.8` → `=0.3.9`（zed@279fe07 → zed@93d7456）を試した。

- 手順: `Cargo.toml` の 2 行を `=0.3.9` に → `cargo update -p gpui-pre -p gpui-pre-platform` → `cargo build -p xirius-ui --release`。
- かかった時間: 版の切り替えと lock の更新が 1 分以内、ワークスペースの再ビルド（sccache の効かない分）が約 4 分。**ソースの修正は 0 箇所**（API の壊れなし。警告も増えなかった）。
- 動作確認: `--bench --scenario still --park` で窓の起動・描画・計測の出力を確かめた。
- 扱い: 上げる作業そのものは確かめられたが、今回のスパイク締めでは変更を最小にするため `=0.3.8` に戻した（`cargo update` で lock も戻る）。次回以降の定期更新は GPUI.md の手順どおりでよい。
