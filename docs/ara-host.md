# ARA のホストの形（PLG-039）

ARA のホストを作る前に決めたことと、その根拠の試し、作ったもの（4）と限界（5）をまとめる。決めたのは次の 3 つ。

1. ARA の API は **C のヘッダー（`ARA_API`）を Rust から直に束縛する**。`ARA_Library` の C++ の殻は使わない。
2. ARA のプラグインは**同じプロセス**で動かす（PLG-015）。落ちても本体が落ちない囲い（PLG-058）は、**ホスト側の例外の囲い**で作る。
3. 囲いで足りないと分かったときの逃げ道は、**ARA だけの別プロセス**（本文の「別プロセスにする場合」）。いまは作らない。

## 1. 束縛の形: C のヘッダーを直に束縛する

2026-10-14 に `Celemony/ARA_SDK` の `releases/2.3.0`（Apache-2.0。`NOTICE.txt` を同梱する。LIC-004）を取って見た。

- ARA の本体は `ARA_API/ARAInterface.h`（3798 行）の **C の構造体と関数ポインター**だけ。ホストが渡すコントローラーは 5 つ（`ARAAudioAccessControllerInterface`・`ARAArchivingControllerInterface`・`ARAContentAccessControllerInterface`・`ARAModelUpdateControllerInterface`・`ARAPlaybackControllerInterface`）、プラグインから受けるのは `ARADocumentControllerInterface` など。どれも `#[repr(C)]` の構造体と `extern "C"` の関数で書ける。
- SDK の `ARA_Examples/MiniHost/MiniHost.c`（540 行）は**純 C のホスト**で、C++ 無しでホストが書けることを示している。Rust で同じ形を書く。
- `ARA_Library/Dispatch/ARAHostDispatch.{h,cpp}`（計 1474 行）は C++ のクラスで、`ARADocumentControllerInterface` などの呼び出しを包むだけ。使うと C++ の殻と C の層が要るうえ、例外と ABI の境が増える。Rust で包み直すほうが小さい。
- VST3 側の結び付け（`ARAVST3.h` の `IMainFactory`・`IPlugInEntryPoint2`）は COM の vtable なので、今の `xirius-vst3` と同じ形で手で書く。CLAP 側は `ARACLAP.h`（拡張の取得だけ）。
- 束縛は、`bindgen` を**手元で一度だけ**走らせて出た Rust のファイルを置く（ビルドで libclang を要求しない）。この PC では Swift の toolchain の `libclang.dll` があるが、CI や他の開発者に libclang を課さないため。ヘッダーは `ARAInterface.h` が C99 で、数百の型だけなので、手直しも小さい。
- 取り込む物: `ARAInterface.h`・`ARAVST3.h`・`ARACLAP.h`・`ARAAudioFileChunks.h` と `LICENSE.txt`・`NOTICE.txt`。`install_JUCE_ARA.cmake` は使わず、取り込まない（JUCE は使わない）。`3rdParty`（cpp-base64・pugixml・ICST AudioFile）は取り込まない。

## 2. 同じプロセスのままで、落ちても本体が落ちないか

ARA はホストのモデルをプラグインが任意のスレッドから読みに来るので、別プロセスに出せない（`ARA_Library`・`ARA_Examples` の汎用の IPC は SDK 側も「後の版に延期」）。PLG-015 はその前提。一方、同じプロセスのプラグインの不正なメモリのアクセスは普通ならプロセスごと落とす。そこで、次の囲いを試した。

### 試した囲い

`crates/xirius-plugins/tests/ara_containment.rs`（Windows の x64 のみ）。

- ホストがプラグインを呼ぶとき、**呼ぶ専用のスレッド**で呼び、そのスレッドに「いまプラグインの中」の目印を付ける。
- プロセスに vectored exception handler を 1 つ付ける。目印の付いたスレッドで `EXCEPTION_ACCESS_VIOLATION` か `EXCEPTION_ILLEGAL_INSTRUCTION` が起きたら、原因を記録して**そのスレッドだけ `ExitThread`**。目印の無いスレッドの例外は触らず、通常の経路に回す。
- 返らない呼び出しは、時間切れ（試験では 150 ms）で見つけて `TerminateThread`。

### 結果

| 起こすこと | 結果 |
|---|---|
| 正常な呼び出し | 戻り値が返る |
| null への書き込み（アクセス違反） | 呼び出しのスレッドだけ終わり、原因が記録され、試験が続く |
| 未定義の命令 | 同じく囲える |
| 返らない呼び出し | 時間切れで見つかり、スレッドを止められる |
| その後の呼び出し | 普通に動く |

### 囲えないこと（この形の限界）

- **ヒープを壊す書き込み**。壊れた後に、無関係の場所で落ちる。落ちた場所がプラグインの外なので、目印では見分けられない。
- **ロックを持ったままのスレッドを終わらせた**とき。ホストとプラグインが共有するロック（メモリ割り当てを含む）が解放されず、あとで固まる。
- **スタックあふれ**（`STATUS_STACK_OVERFLOW`）。ハンドラーを動かす余裕が無いことがある。
- **プラグインが自分で作ったスレッド**での違反。目印が無い。例外の**アドレスがプラグインのモジュールの範囲にあるか**で見分ける形に広げる必要がある（`GetModuleHandleExW` の `FROM_ADDRESS`）。この試験ではまだ試していない。
- **オーディオスレッド**。cpal のコールバックのスレッドを `ExitThread` で止めると音が止まる。プラグインの描画は、ホストの**ワーカースレッド**（`ENG` の並列の実行）で呼び、コールバックは結果の入ったバッファを受けるだけにする。ワーカーが落ちた間は元の音（ARA を付ける前のクリップの音）を鳴らす。試験は無い。

### 決めたこと

- 囲いは上の形で作る。足すもの: モジュールの範囲での見分け、ワーカーで呼ぶこと、落ちたら「落ちた」の状態を立てて PLG-055 の印（色だけ。文は出さない）にすること、再起動の入口（`plugin.restart`）。
- 「囲えない」ものは、囲いを**保証と言わない**。ヒープが壊れたら本体が落ちうる。PLG-058 の `done_when` のうち「落ちても本体が落ちず」は、**アクセス違反・未定義の命令・返らない呼び出し**について満たす。ヒープの破壊・ロックの取りこぼしは満たさない。これを docs と報告に書いておく。
- 実機のプラグイン（Melodyne・Gliss）で、解析中・編集中に落とす試し（PLG-038）で、囲えない落ち方が実際に出るかを確かめる。出るなら、次の別プロセスの形に進む。

### 別プロセスにする場合（逃げ道。いまは作らない）

ARA のプラグインとそのモデルのコントローラーだけを子のプロセスに出し、親は `ARAAudioAccessControllerInterface` などの**親→子の呼び出しを IPC で中継**する。

- 子の側に、ホストのモデル（オーディオソースのサンプル）を**共有メモリ**で見せる。読み出しはプラグインのスレッドから随時来るので、子の中で親のコントローラーのスタブが共有メモリを読む。
- 親の側に、プラグインのコントローラー（`ARADocumentControllerInterface` の 40 ほどの関数）のスタブが要る。
- これは SDK が延期した汎用の IPC を自作することになり、PLG-015 を変える。囲いの結果が悪かったときだけ、PLG-015 を直してから作る。

## 3. 試験の代役（ARA の相手）

- **`xirius_ara::fake`**（`crates/xirius-ara/src/fake.rs`）。Rust で書いた小さな ARA のプラグインで、ファクトリーと文書のコントローラーを直に返す（VST3 の束にはしない）。解析（時間を決められる）・音符・再生の範囲の音（変更ごとの音量）・archive を持ち、ARA の呼び出しの決まり（編集の括り・畳む順・レンダラーを足すのは止めている間だけ ほか）を破ると記録する。`Config` で「解析で不正な読み出し」「描画で戻らない」を起こせる。囲いの試験（PLG-058）はこれで走らせる。
- **SDK の `ARA_Examples/TestPlugIn`**（PLG-038）。C++ で VST3 SDK が要るので、リポジトリには入れず手元で作る（`temporary/` の下）。`XIRIUS_ARA_TEST_PLUGIN` に `ARATestPlugIn.vst3` を指すと `crates/xirius-ara/tests/test_plugin.rs` が通しの手順を走らせ、プラグインの中の assert が 0 のことを確かめる。`#[ignore]` で CI では流れず、`--ignored`（`python scripts/ci_tests.py --plugins`）で流す。指していなければ失敗する。
- 本物のプラグインでの確かめは `docs/ara-verification.md`（PLG-038・PLG-049）。

## 4. 作ったもの（1.1）

- `crates/xirius-ara`: C API の型（`sys`。MSVC で大きさを測って合わせた）、ホストの 5 つの窓口（`host`）、文書の操作（`document`）、VST3・CLAP への結び付け（`vst3`・`clap`。AU は印だけ）、archive の形（`archive`）、囲い（`contain`）、ARA のスレッドとクリップの音（`service`）、代役（`fake`）。
- ARA の呼び出しは、プラグインごとに **1 本の ARA のスレッド**に集める（`Service::start_shared`）。同じプラグインの文書（曲・書き出し・試し）はみな同じスレッドに乗り、順に編集・描画される。Melodyne は最初の文書を作ったスレッドに結び付いていて、別のスレッドで 2 つ目の文書を作ると中で落ちたため（OLE の初期化と窓のメッセージを回すだけでは直らない）。スレッドは OLE を初期化し、窓のメッセージを回す（プラグインの UI のスレッドを兼ねる）。プラグインのコードは `contain::enter` の印の中で呼び、もう 1 本の見張りのスレッドが返らない呼び出しを見る。プラグインの通知は ARA のスレッドで 30 ms ごとに受ける（PLG-034）。
- クリップの音は、解析が済んだ後に**クリップごとの再生レンダラーでオフラインに描き**、エンジンには描いた音を渡す（オーディオのコールバックの中でプラグインを呼ばない）。描き直す間も、落ちた間も、前の音か元のファイルの音を鳴らす（PLG-036・PLG-047・PLG-058）。
- クリップの音は、**ファイルの持つレートのまま**プラグインに渡し、描いた音もそのレートで受けて、鳴らすときに曲のレートへ変換する（PLG-047）。曲のレートを変えても、プラグインには同じ音源のままなので、編集が残る。
- 描画は 1 秒ずつの塊に分け、塊の間に止める・同期の求め・ほかの文書の仕事を受ける（長いクリップを描く間も、ARA のスレッドが答える）。文書を畳むのは止める合図を送るだけで、待たない（待つのはアプリの終わりの `Service::close` だけ）。
- `wait_idle` は、送った同期の番号を ARA のスレッドが処理し終えたかで「済んだ」を見る（送ったばかりの同期の前の状態で返らない）。
- プラグインの初期化（`initializeARAWithConfiguration`）は、プロセスで 1 回、ロックを持たずに呼ぶ。ほかの文書は、それが済むまで最長 35 秒待ち、過ぎたら「初期化が返らない」で止まる。
- archive は、工場の archive id か、工場が読めると言う id のときだけプラグインに渡す（違う種類なら渡さずに「読めない種類」と出す）。曲の archive は、記録したプラグインの id が同じときだけ使う。
- `crates/xirius-session/src/ara.rs`: 曲の ARA の表から `xirius_ara::Song` を作ってプラグインに渡し、描いた音をビルダーの領域に差し込む。プレイヤーの文書が「生きた文書」で、書き出し（別のビルダー）は同じ曲ならレートにかかわらずそれを使い、違うなら生きた文書の archive から自分の文書を作って解析の終わりを待つ（ENG-025、最長 10 秒）。プラグインでの編集の archive は、利用者の履歴の段を足さずに曲に入れる（`take_archives`。ARC-025: 開いただけでは変わらない）。archive は、文書が変わったとプラグインが言ったときにだけ求め、プラグインのスレッドで書かせる。窓のフレームは待たず、届いた後のフレームで曲に入れる（プラグインの窓が先に閉じていても入る）。保存・開き直し・終了の前は、求めた archive の届くのを待つ（1 つにつき最長 5 秒。`begin_pull_states` で先に求めておく）。プレイヤーのために音のファイルを読むのは別のスレッドで、読めたクリップから順にプラグインに渡す（UI のスレッドでファイルを読まない）。頭や尻を切った・中身をずらしたクリップは、描き直すまで、描いた音が覆う所は描いた音、外はファイルの音で鳴る（PLG-036）。
- コマンド: `clip.ara.attach`（プラグインを選ぶのはセッション）→ `clip.ara.attach.apply`、`clip.ara.detach`（EDT-023）。`plugin.status` に ARA のプラグインの行（動いている・落ちた・解析の進み）、`plugin.restart`（id 無し）が落ちた ARA の文書を開き直す。
- 画面（`crates/xirius-ui/src/clip_ara.rs`、形は `docs/ui-approved.md` の「ARA の画面」）: 「処理 ›」の末尾の「ARA プラグインを追加…」（Ctrl+M）と一覧のメニュー、付いたクリップの「〈名前〉で編集」「〈名前〉を外す」（Ctrl+Alt+M）、名前の後ろの印（解析中・済み・落ちた・開けない）。印・ダブルクリック・「で編集」はプラグインの窓（VST3 の editor）を別の窓で開き、1 つのプラグインに 1 窓を使い回す。窓での編集は、archive が届いたフレームで `take_archives` が曲に入れる（UI のスレッドは待たない）。落ちた印を押すと小さいメニュー（プラグイン名・灰色の「編集」・「再起動」・「外す」）が出て、「再起動」（`plugin.restart` と同じ）が ARA の文書も開き直す。

## 5. 囲いの限界と残り

### 囲える落ち方（試験あり）

- ARA のスレッドでのアクセス違反・未定義の命令: アプリのクラッシュ報告のフィルター（`xirius_engine::crash`）が、記録より先に `xirius_ara::contain::last_chance` を呼ぶ。印の付いたスレッドか、登録したプラグインのモジュールの中のスレッドなら、そのスレッドだけ終わる。クリップは元の音で鳴り、`plugin.restart` で開き直せる（`crates/xirius-session/tests/ara_crash.rs`）。
- 返らない呼び出し: 見張りが時間切れで見つけ、ARA のスレッドを止める。
- プラグインが自分で作ったスレッドでの、プラグインのモジュールの中の落ち: そのスレッドだけ終わる。落ちた数をモジュールごとに数え、ARA のスレッドがそれを見て、そのプラグインの文書を「落ちた（プラグイン自身のスレッドで）」にする（`crates/xirius-ara/tests/contain.rs`）。
- ARA のスレッドで Xirius の側が panic したときは、プラグインの落ちとは別の文（「Xirius の誤りで止まった」）で出す。
- 落ちたのはスレッドなので、同じプラグインのほかの文書もいっしょに「落ちた」になる。次に開く文書は新しいスレッドに乗る（`crates/xirius-ara/tests/contain.rs`）。ただし最初のスレッドに結び付くプラグイン（Melodyne）は、アプリを開き直すまで戻らないことがある。

### 囲えない落ち方（保証しない）

- **ヒープの破壊**: 壊れた後に、無関係の場所（プラグインの外）で落ちる。見分けられないので、アプリごと落ちうる。
- **ロックの取りこぼし**: 囲いはスレッドを `ExitThread` で終わらせるので、そのスレッドが持っていたロック（プロセスのヒープのロック・CRT のロック・プラグインの中のロック）は放されない。プラグインが `HeapAlloc` の中で落ちると、後でアプリごと固まりうる。
- **スタックあふれ**: フィルターを動かす余裕が無いことがある。
- **実行のアクセス違反（DEP）を vectored handler が先に見る場合**: アプリの vectored handler はクラッシュ報告を書く（記録だけで、止めない）。その後 last chance で囲えれば続くが、報告は残る。
- 印の無いスレッド（プラグインが作ったスレッド）で、登録したモジュールの外のコードで落ちたもの。プラグインから呼んだシステムや CRT の DLL の中（`memcpy` など）での落ちはこれに当たる（ARA のスレッドでなら囲える）。

これらは囲いの限界で、PLG-058 の「落ちても本体が落ちない」は、上の「囲える落ち方」についてだけ満たす。

### 残り（1.1 の後）

- archive はプラグインが「変わった」と言ったときだけ曲に入れる。編集の無い曲は、開くたびに解析し直す。
- Melodyne は自分の場所に解析のキャッシュを書くことがある（Xirius の曲の外）。
- 音楽の文脈は、曲の最初のテンポと最初の拍子だけを渡す。テンポや拍子の変わる曲では、プラグインの拍の格子がずれる（音の高さと描いた音には響かない）。
- 描いた音は、鳴らすときに曲のレートの `AudioData` に写す（クリップごとに 1 つ持つ）。
- ループしたクリップ（区切りが 2 つ以上）はプラグインを通さず、ファイルの音で鳴る。
- プラグインの編集の archive は、編集があったときに UI のスレッドで取り出す（最長 5 秒待つ）。
- `plugin.restart` に ARA のプラグインの id を渡す形は無い（id 無しの再起動が落ちた ARA の文書も開き直す）。
- 窓の側で動かす場合（windowed）、ほかのトラックからクリップを消した変化は、ARA のトラックが次に組み直されるまでプラグインに届かない。
