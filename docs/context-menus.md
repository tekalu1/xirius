# コンテキストメニュー（承認済み、2026-11-08）

対象の直下は分類入口を含めて最大12行、通常は10行以内。検索欄と余白は行数に含めない。直下に出した操作を分類の中へ重複して置かない。

| 対象 | 直接残す操作 |
|---|---|
| オーディオクリップ | 分割・複製・削除 |
| MIDIクリップ | ピアノロールで開く・分割・複製 |
| トラックの頭 | 名前を変更・チャンネルエディターを開く |
| インサート | 画面を開く・無効にする |
| ノート | 今のグリッドでクオンタイズ・複製・削除 |
| レーンの空き | 貼り付け・MIDIクリップを作成 |

分類の順と担当は全対象で共通。空の分類は出さない。無効な操作のある分類は残し、理由へ到達できるようにする。

| 順 | 分類 | 担当 |
|---:|---|---|
| 1 | 編集 | 切り取り・コピー・貼り付け・複製・名前変更・対象の削除 |
| 2 | 選択 | すべて・トラック上・ループ内・反転・使っているクリップ |
| 3 | クリップ | 分割・結合・ミュート・トランスポーズ値・テイク |
| 4 | オーディオ | テンポ・速さ・微調整・フェード・ゲイン・ノーマライズ・逆再生・ARA |
| 5 | MIDI | クオンタイズ・ノートのピッチ・長さ・ベロシティ・値・CC・MIDI学習 |
| 6 | トラック | トラック・フォルダー・バス追加・出力・センド・フリーズ・トラックプリセット |
| 7 | 機器 | プラグイン・レイヤー・スプリッター・分岐・機器プリセット・サンプル・プロセス |
| 8 | オートメーション | レーン・ポイント・形・範囲変形・マクロ割り当て |
| 9 | 時間 | 再生位置・ループ・マーカー・セクション・テンポ列・拍子・時間の挿入と削除 |
| 10 | 表示 | 色・開く・表示・グリッド・幅・表示行・ブラウザーの見せ方 |
| 11 | 書き出し | バウンス・音声・MIDI・ステム・書き出しカードの再実行と取り込み |
| 12 | ファイル | 所在の修復・収集・整理・フォルダー作成・ごみ箱 |

下層は親の行を残して横に開く。ホバーは240 ms、クリックとタップは即時。右に収まらなければ左へ、下に収まらなければ上へ寄せる。子へ向かう移動中の誤切替を抑える。通常はroot→分類→操作で、値・候補の選択だけもう1段を許す。↑↓で有効な行を選び、→/Enterで開き、←/Escで1段戻る。rootのEscで閉じる。MenuキーとShift+F10でも開く。タッチは長押しで開き、分類をタップして進む。

検索はroot先頭に常設。対象の全子孫の操作名・分類名・経路を検索し、操作名と「分類 › 子分類」を2段で表示する。葉をその場で選べる。無効項目は理由とともに残し、実行しない。Escは文字があればまず消し、次で閉じる。動的候補は、その時点で生成した候補を検索対象にする。

既存項目を消さない。有効条件、無効理由、ショートカット、引数、凍結・クラッシュ時の条件を維持する。名前の変更は「〜名を変更」から「名前を変更…」、「別のチャンネルへ写す」から「別のチャンネルへコピー」の2種類だけ。色は16色の見本、プリセット・送り先は候補リストを保つ。Delayの固定時間18値は通常・付点・3連の各6値に分ける。

## 共通部品の使い方

`context::layout::{Category, Entry, build}` を使う。既存の `Item` に分類を必ず指定し、直接置くときだけ `.direct()` を付ける。分類の日本語名や順序を対象側で再定義しない。

```rust,ignore
let entries = vec![
    Entry::new(Category::Edit, rename).direct(),
    Entry::new(Category::View, color_choices),
    Entry::new(Category::Track, preset_choices),
];
let rows = build(entries)?;
```

`build` は元の `Item` を移動し、引数・キー・状態をそのまま保持する。直下12行を超えた場合は `Error::TooManyRootRows`、余白・見出し・戻るを操作として渡すと `Error::NonOperation`。不明な項目を自動分類するフォールバックは設けない。

ブラウザーへ新しい操作を足す場合も、実際の操作を持つ `Item` を作ってから分類を指定する。FactoryのトラックプリセットをUserへコピーする操作はトラックプリセットの担当である `Category::Track` に置く。機器プリセットの操作は `Category::Device`。候補の名前や識別子を捨てて固定文字列に置き換えない。

既存対象の移行には `Studio::open_classified(target, items, x, y)` を使う。`target` は台帳の `key`、`items` は従来のコマンド・引数・有効条件で生成した木。`context::placement::organize` が台帳の経路へ元の葉を移す。台帳の操作からコマンドを作り直さない。動的候補は生成規則と照合し、実際の名前・値を保持する。新しい操作・対象をこの経路へ追加するときは、台帳にも分類と経路を追加し、実際の木を生成する試験を追加する。未登録の操作は試験で失敗する。

新設するトラックブラウザーなど、承認時の台帳に無い対象は上の `Entry` で分類を指定して `build` し、返った木を `open_context` へ渡せる。`build` の失敗を無視したり、元の平坦なメニューへ置き換えたりしない。試験では実際の候補生成から木を作り、分類・直下の上限・操作引数を検査する。

検索中の数値欄は操作名・経路で並び、選ぶとその位置で数値を編集できる。色は検索結果では色名と見本・経路で並び、通常の子メニューでは16色の見本を保つ。長押しは500 ms、8 pxを超えて動いたら通常のドラッグへ移り、短いタップは元の操作へ渡す。いずれもOSへ入力を送らず、届いた窓の入力だけで処理する。

承認時の927項目は `crates/xirius-ui/tests/context_menus/{inventory,mapping}.json`。台帳同士の一致だけでは実際のシーンでの網羅を証明しない。各シーンが組み立てた木との比較、未分類追加の検出、全条件の行数・順序検査を併せて行う。
