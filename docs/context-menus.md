# コンテキストメニュー（承認済み、2026-11-10）

分類の入れ方は、直下の行数だけで決める。呼び出し側は行の順・余白・見出しをそのまま渡し、形は共通部品が自動で決める（`open_classified` に形を選ぶ引数は無い）。検索欄は全メニューで常に出す。余白と見出しは行数に含めない。

数え方: 葉は1行、呼び出し側の子メニューは1行、色の見本の並びは1行。そのとき見えている行だけ数える。

| 規則 | 内容 |
|---|---|
| R1 | 直下が12行以下なら分類を作らない。行は呼び出し側の順・余白・見出しのまま。二か所に分かれていた子メニューは1つに戻す。 |
| R2 | 直下が13行以上で、行が2つ以上の分類にまたがるときだけ分類を作る。直下は 直接の行（1〜4行、下の表の順）、1行しかない分類の行、分類の順で、12行以内。 |
| R3 | 1行・1件の分類は作らない。その行は直下へ出す。 |
| R4 | すべての行が1つの分類なら、13行以上でも分類を作らない。 |
| R6 | 子を親の横に開いている間は「戻る」を出さず、子の1行目を親の行の高さに合わせる。子が親の幅の半分より多く重なるときは今までどおり「戻る」を出す。←とEscは変えない。 |
| R7 | 呼び出し側の余白は、行を持つパネルの中に残す。先頭・末尾・連続の余白は1つにまとめる。 |
| R8 | 分類の12語と順は変えない。 |

直接の行（分類を作るメニューだけに適用。表の順に並べ、上限は4行）:

| 順 | 行 |
|---:|---|
| 1 | ピアノロールで開く |
| 2 | 画面を開く |
| 3 | 名前を変更… |
| 4 | チャンネルエディターを開く |
| 5 | クリップを結合 |
| 6 | クリップを分割 |
| 7 | クリップを複製 |
| 8 | 無効にする／有効にする（入れ替わる行は同じ位置） |
| 9 | クリップを削除 |

分類の順と担当は全対象で共通（分類を作るメニューのとき）。空の分類は出さない。無効な操作のある分類は残し、理由へ到達できるようにする。

| 順 | 分類 | 担当 |
|---:|---|---|
| 1 | 編集 | 切り取り・コピー・貼り付け・複製・名前変更・対象の削除 |
| 2 | 選択 | すべて・トラック上・ループ内・反転・使っているクリップ |
| 3 | クリップ | 分割・結合・ミュート・トランスポーズ値・テイク |
| 4 | オーディオ | テンポ・速さ・微調整・フェード・ゲイン・ノーマライズ・逆再生・ARA |
| 5 | MIDI | クオンタイズ・ノートのピッチ・長さ・ベロシティ・値・CC・MIDI学習 |
| 6 | トラック | トラック・フォルダー・バス追加・出力・センド・フリーズ・トラックプリセット |
| 7 | 機器 | プラグイン・レイヤー・スプリッター・分岐・機器プリセット・サンプル・プロセス |
| 8 | オートメーション | レーン・ポイント・形・範囲変形・マクロ割り当て |
| 9 | 時間 | 再生位置・ループ・マーカー・セクション・テンポ列・拍子・時間の挿入と削除 |
| 10 | 表示 | 色・開く・表示・グリッド・幅・表示行・ブラウザーの見せ方 |
| 11 | 書き出し | バウンス・音声・MIDI・ステム・書き出しカードの再実行と取り込み |
| 12 | ファイル | 所在の修復・収集・整理・フォルダー作成・ごみ箱 |

下層は親の行を残して横に開く。ホバーは240 ms、クリックとタップは即時。右に収まらなければ左へ、下に収まらなければ上へ寄せる。子へ向かう移動中の誤切替を抑える。通常はroot→分類→操作で、値・候補の選択だけもう1段を許す。↑↓で有効な行を選び、→/Enterで開き、←/Escで1段戻る。rootのEscで閉じる。MenuキーとShift+F10でも開く。タッチは長押しで開き、分類をタップして進む。

検索はroot先頭に常設（行の少ないメニューでも出す）。対象の全子孫の操作名・分類名・経路を検索し、操作名と「分類 › 子分類」を2段で表示する。葉をその場で選べる。無効項目は理由とともに残し、実行しない。Escは文字があればまず消し、次で閉じる。動的候補は、その時点で生成した候補を検索対象にする。

既存項目を消さない。有効条件、無効理由、ショートカット、引数、凍結・クラッシュ時の条件を維持する。名前の変更は「〜名を変更」から「名前を変更…」、「別のチャンネルへ写す」から「別のチャンネルへコピー」の2種類だけ。色は16色の見本、プリセット・送り先は候補リストを保つ。Delayの固定時間18値は通常・付点・3連の各6値に分ける。

## 共通部品の使い方

`context::layout::{Category, Entry, build}` を使う。既存の `Item` に分類を必ず指定し、直接置くときだけ `.direct()` を付ける。分類の日本語名や順序を対象側で再定義しない。

```rust,ignore
let entries = vec![
    Entry::new(Category::Edit, rename).direct(),
    Entry::new(Category::View, color_choices),
    Entry::new(Category::Track, preset_choices),
];
let rows = build(entries)?;
```

`build` は元の `Item` を移動し、引数・キー・状態をそのまま保持する。直下12行を超えた場合は `Error::TooManyRootRows`（R4 の同じ分類だけの行は対象外）、余白・見出し・戻るを操作として渡すと `Error::NonOperation`。不明な項目を自動分類するフォールバックは設けない。

ブラウザーへ新しい操作を足す場合も、実際の操作を持つ `Item` を作ってから分類を指定する。FactoryのトラックプリセットをUserへコピーする操作はトラックプリセットの担当である `Category::Track` に置く。機器プリセットの操作は `Category::Device`。候補の名前や識別子を捨てて固定文字列に置き換えない。

既存対象の移行には `Studio::open_classified(target, items, x, y)` を使う。`target` は台帳の `key`、`items` は従来のコマンド・引数・有効条件で生成した木。`context::placement::organize` が台帳の経路へ元の葉を移す。台帳の操作からコマンドを作り直さない。動的候補は生成規則と照合し、実際の名前・値を保持する。新しい操作・対象をこの経路へ追加するときは、台帳にも分類と経路を追加し、実際の木を生成する試験を追加する。未登録の操作は試験で失敗する。

新設するトラックブラウザーなど、承認時の台帳に無い対象は上の `Entry` で分類を指定して `build` し、返った木を `open_context` へ渡せる。`build` の失敗を無視したり、元の平坦なメニューへ置き換えたりしない。試験では実際の候補生成から木を作り、分類・直下の上限・操作引数を検査する。

検索中の数値欄は操作名・経路で並び、選ぶとその位置で数値を編集できる。色は検索結果では色名と見本・経路で並び、通常の子メニューでは16色の見本を保つ。長押しは500 ms、8 pxを超えて動いたら通常のドラッグへ移り、短いタップは元の操作へ渡す。いずれもOSへ入力を送らず、届いた窓の入力だけで処理する。

承認時の927項目は `crates/xirius-ui/tests/context_menus/{inventory,mapping}.json`。台帳同士の一致だけでは実際のシーンでの網羅を証明しない。各シーンが組み立てた木との比較、未分類追加の検出、全条件の行数・順序検査を併せて行う。

## 形の検査

`placement::organize` は試験のとき、組み立てた木ごとに次を検べる（`verify_shape`）。台帳の全対象を、何も足さない状態と全条件行を出した状態の2通りで通す。

- T1 直下が分類1つだけにならない。T2 1行・1件の分類が無い。T3 直下12行以下で分類が無い。T4 分類を作るとき直接の行は1〜4行で表の順。T5 直下12行以内（R4 は除く）。T10 同じ名前の子メニューが同じ階層に2つ無い。T13 直接の行を足したあとに1行の分類が残らない。
- T7（「戻る」の出し分け）と T11・T12（余白・条件行で形が変わらない）は `context/shape_tests.rs`、T9（入れ替わる行は同じ位置）は `tests/context_layout.rs`、T8（葉が台帳と1対1）は `verify_live_tree`。

## 実際の木の照合

窓を開かないUI試験が `open_classified` を通るたびに、移動前後の葉を一対一で照合する。コマンド・引数・キー・有効条件・理由・選択状態・色の見本・表示名を比較し、台帳の経路、直下12行以内、分類順、固定項目の重複も検査する。候補リストは実際に生成した値ごとに照合する。未登録の葉は分類エラーとして試験を失敗させる。

`scripts/ci_tests.py` は、これらの実木から出たルールIDを `scripts/context_catalog.py` で集計し、承認台帳と補足台帳の未観測・未知IDが一つでもあれば失敗する。保存プリセット、凍結、テイク、接続済み・クラッシュ中のARA、機器の状態別グラフなどは実データ状態を作って生成する。台帳JSONから操作の木を再現して網羅済みにする試験ではない。

承認時の一覧に漏れていた既存操作は原本を変更せず `supplemental.json` に記録する。新しい操作も分類・経路と実際の生成試験を同時に追加する。Delayの同期時間は18候補を通常・付点・3連へ分け、台帳にある「既定に戻す」を独立した行として残す。

## トラックブラウザーへの移行（BRW-017）

機器の行は統合後も `other-70`（音源）・`other-71`（FX）の全操作を引き継ぐ。行の展開矢印からの右クリックも同じ対象として扱う。
索引の機器・マルチ・FX チェーンのプリセットは `track-browser-device-preset`、トラックプリセットは `track-browser-track-preset`、空所・見出しは `track-browser-blank`。
いずれも実際の `Item` を `open_classified` → `placement::organize` → `layout::build` に渡す。
機器プリセットと空所は `other-72`・`other-73` のルールを継承し、元の ID は削除しない。内蔵機器のプリセットと空所には「工場出荷のプリセットを読み込み直す」も残す。
新しいコピー操作とトラックプリセットの操作は補足台帳に追加する。読み込み・User へのコピーは対象に応じて「機器」または「トラック」、お気に入りは「表示」。再スキャンと標準プリセットの復元は「機器」に置く。
直下は分類入口だけの 2 行。Factory/User、FX 付き、マルチ、チェーン、トラックを実際に保存・索引化した UI 試験で、引数・選択状態・無効条件と実木の台帳照合を検証する。

## スタート画面の保存前の曲（UI-351）

「最近の曲」の「（保存前）」の行の右クリックは、「削除」（キー表示 Del）の 1 行だけの共通メニューを開く。
行が 1 つだけで分類する先が無いため、台帳の経路（`open_classified`）は通さず、`bar_tools.rs` と同じく `open_context` に直接渡す。
保存済みの曲・サンプル・空きでは開かず、右クリックは下の曲へも渡さない。選ぶと確認を開く（すぐには消さない）。
メニューキー・Shift+F10 は、選んだ保存前の行で同じメニューを開く。
